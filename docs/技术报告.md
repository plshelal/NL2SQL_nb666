# 金融问数系统 —— 技术报告

## 一、技术路线与解题思路

### 1.1 问题定义

面向零售银行的 NL2SQL 智能问数系统。业务人员以自然语言提出查询需求（如"江苏省A市农商行2025年6月各项存款余额是多少？""从规模、质量、效益三个维度分析C市农商行2026年4月末的表现"），系统自动理解语义、生成 SQL 并执行查询，返回表格、图表和分析报告。核心挑战包括：口语模糊表达到数据库字段的精确映射、复杂嵌套查询的 SQL 生成、多轮对话上下文理解、权限安全控制。

### 1.2 整体架构

采用 LangGraph 编排的 14 节点智能体工作流，以"理解→生成→管控→展示"四层递进为设计主线：

- **理解层**：jieba 分词 → Schema Link 语义分流 → LLM 关键词扩展 → TEI 向量化 → 三路并行召回（Qdrant 向量字段/指标召回 + ES IK 分词维度值召回）→ 合并去重
- **生成层**：LLM 并行过滤表与指标 → 两步思维链 SQL 生成（先列目标字段由系统判权，再带约束生成）→ EXPLAIN 语法校验
- **管控层**：SQL 执行后 Python 层逐行白名单过滤 → 排名全为 1 自动重试 → 缺失信息兜底提示
- **展示层**：SSE 双通道数据先行推送表格 → LLM 异步匹配图表类型（柱状/折线/饼图/数字卡片）+ 生成分析报告

遵循"LLM 可感知充分注入、不可靠环节独立兜底、安全合规零侵入"原则。

## 二、模型架构与关键技术

### 2.1 LangGraph 智能体编排

14 个节点通过 DAG 定义执行顺序，state 在节点间传递上下文，条件边实现动态路由：

```
extract_keywords → schema_link → expand_keywords → [recall_column ‖ recall_metric ‖ recall_value]
→ merge_retrieved_info → [filter_table ‖ filter_metric] → add_extra_context → generate_sql
→ validate_sql → [correct_sql ←→ execute_sql]
```

关键条件边：(1) validate_sql 语法失败路由至 correct_sql 纠错后重执行；(2) generate_sql 权限拦截直接 END 跳过后续节点；(3) execute_sql 检测到排名全为 1 自动触发 correct_sql 重生成。

### 2.2 Schema Link 语义分流

在关键词扩展前增加一次 LLM 语义分析，从 `meta_config.yaml` 中读取 8 个预定义指标组（规模、资产质量、盈利能力、结构、效率、客户经营、监管、人员），每组含描述和成员指标列表。根据用户问题判断类型：

- **group**：命中指标组，锁定成员指标直接注入关键词列表，减少 Qdrant 搜索量
- **computed**：计算指标，查 `indicator_formula` 表取 SQL 模板和组件指标
- **normal**：普通直接指标查询，正常走三路召回

此机制在零额外搜索开销下，将模糊指标组查询的准确率提升至接近直接指标查询水平。

### 2.3 三路并行召回

- **Qdrant 向量检索字段**：TEI（bge-large-zh-v1.5，1024 维）将扩展关键词批量向量化，在字段名/描述/别名的向量库中做余弦相似度检索，取 top-N 相关字段
- **Qdrant 向量检索指标**：同机制检索指标名/描述/别名的向量库
- **ES IK 全文检索维度值**：关键词经 IK 分词器穷举切词，在数据库真实取值索引中做全文匹配，验证"不良贷款率""江苏省A市农商行"等维度值真实存在

三路并行通过 `asyncio.gather` 实现，结果在 merge 节点去重合并，并按表分组、关联主外键。

### 2.4 两步思维链 SQL 生成

DeepSeek 路径采用两阶段生成：

**Step 1 —— 字段规划**：LLM 先列出计划使用的机构名称和指标名称，系统进行笛卡尔积权限判定（机构白名单 × 指标白名单），全部越权则拦截返回，部分越权筛掉非法组合后继续。

**Step 2 —— SQL 生成**：系统提示注入业务规则（排名方向、日期计算、增幅公式、机构名称格式、指标单位规则、禁止脑补缺失信息），结合对话历史和动态 Few-shot RAG 示例生成最终 SQL。

Qwen 微调路径可单独配置，通过环境变量 `SQL_MODEL=local` 切换至远程推理服务。

### 2.5 动态 Few-shot RAG

120 条训练数据的问题文本预计算为向量并缓存文件。每次查询时，TEI 将用户问题向量化后做余弦相似度检索，取 top-3 最相似训练样本的"问题→SQL"对作为动态示例注入生成提示词。示例向量缓存启动时加载，查询时毫秒级检索。

### 2.6 计算指标公式表

`indicator_formula` 数据库表预设 30 个计算指标的 SQL 模板、组件指标列表和别名数组。查询扩展阶段对所有关键词做精确字符串匹配（含别名），命中则注入生成提示词，完全排除 LLM 对计算逻辑的猜测和幻觉。

### 2.7 上下文多轮对话

前端维护对话历史栈，每轮完成后将用户问题与系统返回结果存储为问答对。新一轮提问时，将最近几轮问答以自然对话格式（"用户: ... / 系统: ..."）注入系统提示。LLM 自行理解"那B市呢""重新查询""换个角度"等指代与省略，无需规则硬编码。

### 2.8 权限安全控制

SQL 执行后 Python 层逐行白名单过滤：从 `role_permission` 和 `users` 表查询用户岗位对应的指标白名单和机构白名单，遍历返回结果每行逐值扫描是否包含禁止指标名或机构名。被过滤行计入日志，空结果时统一提示用户检查权限或查询条件。LLM 生成链路完全无感知权限存在，实现零侵入的行级安全控制。

### 2.9 缺失信息兜底

若生成 SQL 中无 `data_date` 过滤条件，系统自动注入 `data_date='1900-01-01'` 使查询自然返回空，触发前端"无数据返回。请检查是否遗漏日期/机构/指标，或确认您的权限是否包含该项数据"统一提示。机构名支持简写自动修复——"A市农商行"补全为"江苏省A市农商行"。

### 2.10 可视化与归因

SSE 双通道架构：数据先行推送表格（0 延迟），LLM 异步分析数据特征匹配图表类型（单值→数字卡片 / 对比→柱状图 / 时序→折线图 / 占比→饼图），生成 JSON 配置由 Chart.js 异步渲染。同时 LLM 生成 80-150 字金融视角分析报告。图表和报告均不阻塞数据展示，失败降级为纯表格。

## 三、实验设计与结果

### 3.1 数据集

核心数据为 13 家江苏省农商行的日频经营指标，含 21 个直接指标（ZB001-ZB021），时间跨度约 2 年，总量约 13 万行。基于此构建 120 条训练问题（含简单/普通/复杂三个难度等级）和 80 条验证+测试问题。

### 3.2 关键指标

| 指标 | 结果 |
|------|------|
| 验证+测试集正确率 | 78/80 (97.5%) |
| 简单(S)平均耗时 | 12.4s |
| 普通(M)平均耗时 | 12.2s |
| 复杂(H)平均耗时 | 19.5s |
| 总平均耗时 | 14.4s |

注：耗时主要为 DeepSeek API 网络延迟，本地 TEI 向量化和 Qdrant 搜索为毫秒级。API 调用次数约 5-7 次（含思维链）。

### 3.3 微调尝试

尝试使用 Qwen2.5-7B 对 SQL 生成节点进行 QLoRA 微调，训练数据为 120 条标注的 question-SQL 对。微调后模型在基础查询上表现可接受，但在复杂嵌套查询（多表 JOIN、窗口函数、CTE 嵌套）和计算指标（同比/环比/增幅）场景下泛化能力不足，准确率低于 DeepSeek 云端推理。分析原因：120 条训练样本的查询类型覆盖不够充分，且 7B 模型在复杂 SQL 生成任务上的能力上限低于 685B 参数规模的 DeepSeek。该方向后续需扩充训练数据规模和引入推理增强技术。
