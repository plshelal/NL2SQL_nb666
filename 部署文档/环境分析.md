## 四、部署执行计划（严格按 README 手动安装流程）

1. 配置 `.env`（DB_PASSWORD=123321，DEEPSEEK_API_KEY 待用户提供）
2. `docker compose -f docker\docker-compose.yaml up -d --build`（MySQL + Qdrant + ES + TEI）
3. `uv sync`（安装 Python 依赖）
4. `uv run init_db.py`（创建 meta / finance 两库表结构）
5. 导入预置数据（meta_data.sql + finance_data.sql，59 用户 + 105 权限 + 30 公式 + 13 万行指标）
6. `uv run -m app.scripts.build_meta_knowledge -c conf/meta_config.yaml`（构建 Qdrant 向量 + ES 全文索引）
7. `uv run -m app.scripts.seed_permissions`（导入 CSV 权限，README 步骤 6）
8. `uv run -m app.main`（启动应用，访问 http://localhost:8000/static/query.html）

每一步的执行结果、报错信息与解决方法将记录在《部署日志与错误记录.md》。

### 5.2 实测发现的 README 不可靠点（部署受阻，需修复才能继续）

| # | README 声明 | 实测问题 | 严重程度 | 修复方式 |
|---|---|---|---|---|
| 1 | 「模型文件已预打包在 `docker/tei-model/`，无需联网下载」（第 201 行） | 压缩包**无 `docker/tei-model/` 目录**，TEI 容器挂载空目录将加载模型失败 | 🔴 高（TEI 服务无法启动） | 手动从 hf-mirror.com 下载 bge-large-zh-v1.5（1.24GB）到 `docker/tei-model/` |
| 2 | 「从 `conf/` 下的 CSV 文件导入岗位-指标权限和用户账号」（步骤 6） | 压缩包**无 CSV 文件**，脚本 fallback 到开发者本机路径，`seed_permissions` 必然报 FileNotFoundError | 🟡 中（install.bat 用 `2>nul` 忽略；权限已由 dump 预置） | 无需处理，或自建 CSV |
| 3 | 「`finetune_data.json` 启动时自动重建」（目录结构） | 代码 `fewshot_rag.py` **直接读取**该文件，无重建逻辑；文件缺失导致**应用启动直接崩溃** | 🔴 高（应用无法启动） | 手动创建空 `conf/finetune_data.json` |
| 4 | 目录结构含 `conf/finetune_data.json` | 实际压缩包中为 `conf/fewshot_embeddings.pkl` | 🟢 低（文档不一致） | — |

### 5.3 项目自身代码缺陷（非文档问题）

| # | 位置 | 问题 | 影响 | 修复 |
|---|---|---|---|---|
| 1 | `app/conf/meta_config.py` | `MetaConfig` 缺 `indicator_groups` 字段，与 `conf/meta_config.yaml` 不一致 | 步骤 5 构建知识索引直接报 ConfigKeyError | 补充 `IndicatorGroupConfig` 数据类 |

### 5.4 环境类问题（与本机网络/沙箱相关，非项目缺陷）

| # | 问题 | 解决 |
|---|---|---|
| 1 | uv 默认缓存目录在沙箱外（AppData）被拒 | `UV_CACHE_DIR` 重定向到工作区 |
| 2 | antlr4-python3-runtime 4.9.3 源码构建 PermissionError | 清缓存 + 完全访问权限重跑 |
| 3 | Docker 镜像加速源失效（USTC 域名过期等）导致 ES 大层 40KB/s | 更换可用源（docker.1ms.run 等）后 17.6MB/s |
| 4 | 清华 PyPI 源返回空版本列表 | Dockerfile.tei 改用阿里云源 |

**总结**：README 的主流程（环境要求、服务清单、数据规模、账号）真实可靠；但压缩包存在 3 处与实际不符的缺失（tei-model 模型目录、权限 CSV、finetune_data.json）和 1 处代码 bug（MetaConfig），导致严格按 README 执行时在步骤 1（TEI 模型）、步骤 5（知识索引）、步骤 7（应用启动）受阻——README 的**总体可靠性约为 70%**，需配合本文档的修复方案才能完整部署。
